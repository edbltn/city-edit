Street View pegman on proposal modals

2026-07-28 · branch main
1 VerificationChecklistFull diff

The pinned point-proposal modal now carries a small yellow Street View pegman that opens Google Street View at the selection's coordinates, so you can eyeball the actual street before voting. Route cards deliberately don't get one — a route isn't a single place you can stand.

React client

1 · A pegman on every proposal modal

Goal

Judging a proposal ("does this corner really need a wider sidewalk?") means knowing what the place looks like. The pinned point-proposal card now carries a small Street View pegman that opens Google Street View at the selection's coordinates in a new tab.

Design

  • The link uses the Google Maps URLs API (maps/@?api=1&map_action=pano&viewpoint=lat,lng) — no API key, no embed; Google resolves the nearest pano to the viewpoint and falls back to the map when none exists.
  • ProposalCard only receives screen coordinates, so the geographic anchor arrives as a new streetViewLatLng prop, passed ONLY by the pinned point card: pinnedPointLatLng is the graph-snapped point, so Street View opens where the pin sits, not where the click landed. Route-summary cards deliberately omit it — a route spans many blocks, so one pano would be misleading — and hover cards stay tool-free.
  • The pegman is an inline SVG in Street View's signature yellow (#FBBC04) so it reads as "Street View" at 13px, sitting first in the tools row before copy-link / minimize / ✕.

What changed

  • GraphLayer.tsx: PegmanIcon, the streetViewLatLng prop, the <a> tool in graph-proposal-tools, and the pinned-point call-site wiring.
  • globals.css: .graph-proposal-streetview (anchor styled as a tool button) and the interactive card's header clearance widened 80px → 106px for the fourth tool.

Files touched

  • client-react/src/components/GraphLayer/GraphLayer.tsx — PegmanIcon + streetViewLatLng prop + tool link + wiring
  • client-react/src/styles/globals.css — anchor tool styling, 4-tool header clearance
Verification

What was run

  • Frontend: tsc --noEmit — clean; vite build — clean.
  • Live dev (localhost:3000, nyc-walkways): point selection → Proposal card shows the pegman and its link targets the snapped coordinates; start+end route → Route Proposal card shows NO pegman. Header text clears the tools.
For you

Manual checklist

  • On prod, select a point and click the pegman — Street View should open at that corner in a new tab (try somewhere you know, e.g. a Manhattan intersection).
  • Select a full route — the Route Proposal card should show NO pegman (routes span many blocks; a single pano would mislead).
  • Confirm hover cards (mouse over a proposal icon without clicking) show no pegman.
  • On a narrow window, confirm the card's title row doesn't collide with the four tool buttons.
