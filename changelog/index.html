Aesthetic fixes — slimmer selection rings, and an incandescent tip for the heat ramp

Two visual fixes, verified live: the selected double border on top-proposal markers is now a true 2.25px contour of the outer shape on every marker kind — replacing the point pin's 3px inset and the route diamond's uneven hand-placed ≈3.5–4.2px one, so diamonds and pins carry identical-weight rings with more air around the glyph. Every ramp now extends past peak into a computed incandescent tip (white-hot on dark basemaps, ink-dark on light ones), stops respaced to 0/.35/.65/.85/1, the block fill spans the full heat domain with a heat-driven outline width, and the canvas hottest-edge accent strokes the tip — legend, canvas heatmap, proposal pins, and block fill all still agree.
2026-07-07

Junction clusters, capture mapping, and the stale-heat guards

Round two on junction blocks, from live screenshots: intersections drew as stacked overlapping circles (a physical intersection is many OSM junction nodes — 94% of NYC's junctions have a neighbour within 24 m), band cutouts looked misaligned (bites from invisible sibling discs), and voted node blocks stayed dark on the heatmap. Overlapping discs now merge into one multi-node block per junction cluster (415,967 discs → 99,535 blobs, radius 12 → 9 m), and nodes get their own mapping rule: the bake's new junction-capture pass maps any edge midpoint within 12 m of a junction to that junction's block by graph distance — 5,351/5,351 midtown crossing stubs land in junction blocks, 0 perpendicular, 0 unmapped. The dark heatmap was a stale-cache class, not rendering: block ids renumber on re-bake under the same topology etag AND revision, so the boot painted a pre-re-bake IndexedDB votes body and deltas layered onto it — closed by an n_blocks/blocks_version guard on the votes cache, a blocks-mtime stamp in the graph-votes ETag, and a pid-unique tmp for the geojson writers (two pipeline runs interleaving one shared .tmp corrupted 300 MB of blocks mid-rebuild).

RBTP parity — mixed cluster fan-out, corridor drops, people-not-blocks vote counts, and a route ✕

Five requests bringing the route-proposal diamonds to full parity with the point pins. Diamonds now fan out with crowded point-pin clusters (one mixed grid; diamond clicks explode-before-select like the squares); dropping any waypoint — a dragged mid, a fresh path-drag ghost, or an exploded-proposal drag — onto a diamond threads the route through the WHOLE corridor, inserting its two anchors in whichever order gives the shorter prev→anchor→…→anchor→next chain, and the selected diamond carries the same [×] the matched point pins have (removes both anchors atomically). The route card's vote rows now count distinct people via a new POST /api/route-votes (COUNT(DISTINCT device_id) per vote type and direction — a route cast used to count once per block it fanned across; verified against the DB: 912 fanned rows → up 2 / down 1); the meta line reads “Selects N blocks”; and a new ✕ on the card deselects the entire route in one tap. Round 2: a slow unmoved press is a TAP again (time-only gesture detection was turning careful diamond clicks into zero-distance drag-drops that threaded corridors repeatedly — new TAP_MAX_DRIFT_PX, max-drift-tracked), taps landing on a diamond's box select it, re-taps of a selected diamond are no-ops, and a selected RBTP now routes through its corridor VERBATIM — the proposal's stored path replaces the OSRM leg between its anchors (corridorCoordinates + a registered anchors→corridor resolver consulted by every segment calc), so the drawn route, heat/hover highlight, coverage ring, and vote target all trace the same corridor.

2026-07-05

MapLibre ↔ Leaflet position drift — zoom off-by-one + riding the zoom animation

The post-restyle “position drift” was two camera bugs between the renderers that now share the screen. Leaflet defines zoom against 256px world tiles, MapLibre against 512px — passing the zoom straight through ran the GL base map + block heat at exactly 2× Leaflet's scale, aligned only at the screen center (measured: 117 px vs 233 px for the same probe point). And during animated zooms Leaflet suppresses move events, freezing the GL map for 250 ms while pins glided. Fixed with a −1 zoom offset plus a zoomanim CSS-transition ride on the GL container using Leaflet's exact curve; verified sub-pixel in the live app.
2026-07-04

Three-layer voting model — graph · blocks · route proposals

The edge/node graph stays the storage source of truth; procedural per-city blocks (median IoU 0.84 vs NYC planimetric ground truth) become the aggregation/display/interaction grain — votes deduped once per voter, block-scoped clear-then-cast in /api/vote so a block never holds + and − from one device; route proposals are now computed deterministically on the client (server Leiden engine removed). Plus a critical fix: the packed vote-type field widened 16 → 24 bits — ids past 65,535 were overflowing into the direction bit and recording as downvotes.
2026-06-17

The mobile-Safari heatmap crash was the graph's own memory

"A problem repeatedly occurred" on phones (bikepaths and the other NYC street maps) wasn't the server, the subdomain routing, or vote-sync — those were ruled out one by one. The foot-aligned rebuild doubled the NYC graph to 3.3M edges, and the client decoded its 35 MB binary blob into ~497 MB of boxed JS tuples, over mobile Safari's per-tab budget. Backed the topology with flat typed arrays (coords/ends + CSR adjacency) read through accessors — ~497 MB → ~71 MB, off the object heap entirely.
2026-06-17

Unifying the icon-explode model — one cluster fanned out at a time

Crowded proposal icons fan out ("explode") into a grid so you can pick one from a stack. The state behind it was two overlapping spread maps merged on every render — built to keep several clusters open at once. Collapsed them into a single spread plus a lock flag, routed all cluster detection through one clusterAround() helper and collapsing through one collapseSpread(), and made a fresh fanout replace the open one — so exploding any icon set un-explodes the others.
2026-06-17

Removing ferry edges from routing and the display graph

Ferry ways tagged foot=yes (Staten Island Ferry, Governors Island, NYC Ferry…) were slipping past the "ferries disabled" foot profile via an access fallback shared by OSRM and its Python mirror — so routes jumped open water and ferry lines lingered in the hover graph. Added an explicit route=ferry cutoff to both, rebuilt every graph + the OSRM dataset, and added a reverse-coverage check that keeps the two graphs consistent.
