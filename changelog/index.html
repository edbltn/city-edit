Audience: view counts and co-presence, built so the number can be believed

Two features whose product is common knowledge — "we are looking at this together, and we both know it" — which inverts the usual analytics instinct: over-counting destroys the effect outright, under-counting costs a little, and every trade resolves in that direction. Neither reads device_id, whose localStorage preimage is currently fragmenting (one iPhone, six voter_ids, three minutes on prod); keyed on it both counts would rise exactly as identity degrades — the failure that looks like success and is invisible from outside. Both key on the hashed IP votes already count by, and on nothing the client sends. The view count could not be built the obvious way: a route proposal has no durable id — RouteProposal.id hashes the corridor's path edges and rotates on the next vote, which the client already treats as its "corridor moved" signal. So sketches are stored per block and the proposal is named only at read time, as a set of blocks: PFCOUNT over many keys returns the union, so one person who opens two blocks of one corridor counts once by construction. Measured on a real 22-block corridor: naive sum 25, union 4. Co-presence is a sorted set and deliberately not a sketch, because a room has to be able to empty — hidden tabs leave immediately, departure is explicit rather than left to expiry, and the count is correct across replicas. Both ride the WebSocket that already exists: four JSON messages, no second channel, no codec bump. The UI draws one mark per person with yours filled, so the number can be counted against the sentence.

Three ways a map lied about itself

Three complaints about nyc-tactical, and in all three the map was faithfully reporting state that was itself wrong. Vote types "came back" that had never left: row xmin puts the map row's last write 146,000 transactions before the oldest vote cast on it, so the earlier removal landed in some other database and printed a checkmark anyway — load_dotenv() supplies the local url to anyone who forgets an inline prod one, and an UPDATE matching zero rows is not an error. The CLI now names its database and reads its write back. Two tied proposals 12 km apart drew a single pin, and the 1 km spacing radius was innocent: the per-type cap is applied before the spacing pass and breaks ties by edge index, which is graph build order — so all five slots went to blocks inside a 228 m stretch of one cast and the other neighbourhood was never a candidate at all. Ties are the normal state of a young map, where every proposal has exactly one supporter. Slots are now filled with blocks that are actually apart, and the radius halves to 500 m. The third was a request to give those votes a route analog, which turned out to cost five changes rather than one — the binding one a corridor support floor of 101 that would have silently discarded the smaller of the two casts, measured by replaying all 189 prod votes onto a local graph rather than by predicting it. Both casts now draw as corridors on prod, at +128 and +59.

A binary vote frame, and a sync packet for backgrounded tabs

The WebSocket vote stream was JSON, and a median 89-edge route cast spent 3,316 bytes saying about 150 numbers — every edge id sent twice, every one quoted as a decimal string. It is now a canonical binary frame at 508 bytes, because a route's edge ids are near-consecutive (median gap: 6) and so they sort and delta-varint encode, with the vote type hoisted out of every cell. The width discipline is the lesson from this codec's predecessor, where a 16-bit vote_type_id overflowed into the direction bit and recorded upvotes as downvotes: growable fields are varints, which are self-delimiting and cannot bleed into a neighbour, and they are paid for once per group rather than once per cell. The second half is new — a sync packet the client asks for on foreground and reconnect, carrying only the cells that moved while it was hidden, and marked TRUNCATED unless the server's log can prove it covers the gap. That repair used to be a whole-city /api/graph-votes refetch: 1.78 MB on nyc-bikes, measured against prod. And the fuzz test earned its keep three times — non-canonical varints, cell ids that collapsed into each other, and a lossy UTF-8 decode that would have invented a phantom vote type, each one a corrupted frame that decoded successfully into something different. Auditing the other paths for a lingering 16-bit vt then found the July bug still live one field over: block_votes.pack_block_field wrapped silently at 224, turning an upvote into a downvote on the block layer. New vote types are now refused at creation, loudly, at 16,777,215 — the narrowest of the three packed layouts, not the 2.1 billion the Postgres SERIAL can mint.

Words on the map: a text tier for top proposals

A proposal pin can say that something is wanted somewhere; it cannot say what. This draws the words — the claim in caps with its vote count under it — beside each top-proposal pin. They are drawn as a MapLibre symbol layer rather than as markup on the pin, so the decluttering is not ours to write: MapLibre runs one collision index across every symbol layer, placement starts at the topmost layer, and adding this one above the place labels means proposals claim their space first and the POI names step aside. Each symbol also carries a transparent 34×42 puck matching the Leaflet pin's footprint, so a business name can no longer land underneath a pin — which it could before. And these are the one text tier allowed to be vivid: POI_MUTE exists to buy the proposals that headroom, and it was all being spent on pin shapes and glow rings, the two channels least able to carry meaning. Making the contrast floor a ratio over the place labels rather than a fixed number caught two accents the eye had not — transit's blue at 5.7:1 against near-black, under the muted labels it was supposed to outrank, and trees' green at 5.0:1 inside the POI band on paper.

The vote-type toggle, measured: one second down to one frame

Hiding a vote type in the legend took about a second to show anything, for a change that alters no votes at all. Measuring first — with a harness that records the click, the synchronous handler, every idle callback, long tasks and the first WebGL draw, which is the only honest signal for “the map changed” — found two separate stalls, and neither was where the code's own comments predicted. The heat repaint was rewriting all 42,524 lit blocks' feature-state because the filter had nudged one normalization ceiling from 93 to 80; hiding a type that changes fifteen blocks repainted the whole city. And the pins and corridors were being reclustered from scratch behind an idle callback — ~800ms of work whose result, per vote type, was byte-identical to what was already on screen, because a corridor for one type never depended on whether its neighbours in the legend were shown. Both are now caches keyed on a vote epoch (not the server revision — the optimistic cast edits vote state in place without advancing it), the visibility filter moved out of the O(edges) scans and into the cheap selection step that follows them — still before selection, so hiding a type keeps promoting another type's runner-up into the freed slot — and the whole toggle now runs synchronously in the click: heat 273ms → 29ms, proposals 1,023ms → 12ms.

Stickers: a QR code on a pole that learns where it is

Round die-cut stickers carrying one line of text and one QR code, and a scan flow built around the fact that the sticker does not know where it is. Every sticker gets its own code; the first person to scan one shares their location and votes, and that vote — not the shared location — pins the code to that spot, so every scan afterwards goes straight to the vote there and nobody is ever asked twice. Refusing location is a supported ending, and deliberately does not pin the sticker: a hand-placed pin says where the user guessed, not where the sticker is. Two print stocks confirmed before anything was drawn, with both die grids re-derived to close exactly on a Letter sheet and bleed capped at half the gap to the next label. The type is solved, not laid out — a line inside a circle is measured by a chord, so the art tries one, two and three line stacks and prints whichever sets biggest, taking “Tired of waiting?” from 10 pt to 15.6. The URL is uppercase so it lands in QR's alphanumeric mode and fits a 29-module code at the highest error correction. All 216 stickers were rasterised and decoded back, one at a time, against the manifest. A follow-up pass fixed the line being hard to read — the cause was that the print PNGs were transparent, so Preview composited near-black type onto its grey ground; they are flattened onto white now, and the type went to the font's heaviest weight (free, since a monospace advance is weight-invariant) and up to 13.3–21.3 pt. The same pass added an optional bridge to qrart, which paints the code with Stable Diffusion and still scans — kept at arm's length in its own interpreter so no torch dependency reaches this pipeline, and gated on the painted code decoding to that sticker's own URL.

The longest waits: ranking every NYC crossing by the time it takes

The dangerous-intersections campaign answered where do people get hit. This one answers where does the city waste people's time — the wait to cross, multiplied by the crowd that has to stand in it. Neither number is published, so both are modelled: the wait from signal engineering plus OpenStreetMap carriageway topology, the crowd from a fit on the 95 corners where DOT actually counts (leave-one-out R² 0.71). The subtle part is staged crossings — counting signal nodes calls the West Village's cluster of ordinary corners a four-stage boulevard, so the model instead groups each street's OSM ways into connected components and counts only the carriageways the cross street actually reaches. Queens Boulevard, Woodhaven, Ocean Parkway and the Grand Concourse fall out on top, which is the answer a New Yorker would give. Across 11,907 signalised crossings it comes to 406,000 person-hours a weekday spent standing at a kerb. The output is a 36-poster packet whose hero figure is an outline and whose one large field of colour is a hatch, because a poster nobody can afford to print does not get printed.

The heatmap blocks that vanished when you zoomed out

Zoom out two steps from the default view and most of the heat disappeared — worst of all over Manhattan, while Brooklyn stayed lit. The block layer is not decoration: it is the heatmap's geometry, addressed by feature id, so a block tippecanoe thins out of a tile cannot be lit no matter how many votes it has — and tippecanoe thins in proportion to density, which is a proxy for where the votes are. NYC was carrying 61% of its blocks at leaflet 13, 24% at leaflet 12 and 17% at leaflet 11. The fix costs nothing anyone can see: the tiles were mostly seven display attributes that no code reads, so dropping them (--include=block_id), keeping sub-pixel blocks as themselves (--no-tiny-polygon-reduction) and raising the per-tile ceiling makes every served zoom complete — in an archive that is 20% smaller than the thinned one. And because this hid for months behind a perfect default view, the bake now counts blocks-per-zoom and refuses to install an archive with holes.

Putting names back on the map — streets, places and businesses

The basemap was deliberately label-free so nothing competed with the vote heat, and the cost was a map that couldn't tell Canarsie from Corona. Names are back in two tiers. Streets, neighborhoods and water come from CARTO's labels-only raster, drawn above the heat — the split basemap is the whole trick, since a labelled basemap would bury every street name under a translucent hot block. Businesses and civic landmarks come from our own OSM extract, because CARTO's tiles carry none at any zoom. That half is all curation: the five commonest named POI tags in NYC are subway platforms (15,688, one per track), restaurants, named rail segments (10,675), places of worship and abandoned track — so an allowlist cuts 210,003 features to 34,349, and a grid-thinning pass sets each label's reveal zoom so the density cap is geometric and holds in Midtown and Canarsie alike. Three things only showed up by looking: quarter-tile cells read as a directory (~50 labels), subway stops share Grand Central's tag and carpeted the low zooms as fake street labels, and parks — the one thing CARTO does label — printed twice in two fonts. Labels are colored by category in Red Hat Mono, which meant self-hosting SDF glyphs and retiring a live dependency on MapLibre's demo server. Then a second round: the fix for those carpeting subway stops had overcorrected so hard the stops effectively vanished — rank 64 sits near the bottom of everything eligible at z15, so every grid cell went to a museum or hospital first and six East Village stations rendered as one.
