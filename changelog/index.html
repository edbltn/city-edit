2026-07-08

Node/edge parity — the ends of every segment belong to their nodes

Nodes are now as easy to select as edges. A pixel radius structurally can't do it (every node IS an edge endpoint, so the nearest edge is always at least as close), and an absolute-priority disc fails both ways with zoom — so the hit-test now splits each edge's catchment area by the projection parameter: the outer quarter at each end belongs to that end's node, scale-invariant at every zoom. hitTest subsumed the uncapped nearest-edge fallback (findNearestEdgeIndex deleted) and the node index left the hot path. Hover and click also share one gated resolver end to end (sticky proposal → block hierarchy → radius-bounded → nothing far from the graph), closing two hover≠click gaps: far-from-graph hover highlighting what a click can't pin, and the top-proposal sticky annulus showing a graph node while the click links to the proposal. Acceptance: 20 random clicks on test-central-park → 10 nodes / 10 edges, 20/20 pins identical to hover.
2026-07-08

Top-proposal rework — route/point kinds end-to-end, one pin per block, corridors earn their length

Route-flavored vote types (“Add bike greenway”) could masquerade as square point pins because the route/point kind died at the config boundary: presets declared pointType but the global vote_types registry, the suggestion-creating cast, and the searched custom types all dropped it — and the proposal selectors never looked. Now the kind rides end-to-end (vote_types.point_type column, cast records the kind of a brand-new suggestion, searchVoteTypes serves {label, pointType}, startup backfill repairs legacy rows from every authored list — 50 stamped locally) and the families are disjoint: point-kind → PBTP squares only, route-kind → RBTP diamonds only, unknown legacy kinds stay eligible for both. Point pins also obey the block grain (one pin per street block across ALL types) with same-type spacing widened 300→600 m. Route corridors get a support-scaled meter budget (600 + 150·√score, ≤ 2.5 km): each peeled path is trimmed to its hottest contiguous window, so a chain of stray net-1 edges can't stretch a proposal across the borough. Plus a latent greedyHeaviestPath splice bug (duplicated seed node) the trimming exposed.
2026-07-08

Agent load test — the vote pipeline saturates at ~9 votes/s

Tiered load test (5 → 160 simulated voter agents, each a real client: WebSocket + graph-votes fetch + route→vote cycles) against a fresh NYC map. Voting saturated at ~8–9 votes/s from 20 agents on; at 160 agents the app functionally locked up — 13% of votes blew a 45 s timeout (p95 45.6 s), 11 graph-votes bodies truncated mid-stream, Flask RSS doubled to 7.1 GB — while /health stayed at 1–2 ms throughout. Root cause: every vote serializes through the process-wide _proposal_vote_lock with ~300–550 sequential Redis round trips (per-edge apply_directional/apply_block_delta) plus a synchronous Postgres write inside it. Report includes the tier-by-tier data, six ranked findings, and a mitigation plan: batch the Redis writes into ≤3 pipelines, narrow the lock to per-voter, cached-gzip + debounced graph-votes snapshots, coalesced WS broadcasts, and load-shedding + a real saturation signal.
2026-07-08

Phantom path-hover pockets + the Top Route Proposal that wouldn't let go

The “ghost waypoint hover triggers far from the route” dead zones were SVG hit-testing: pointer-events: all on the desire path's invisible 20px interactive stroke also hit-tests the path's unpainted interior fill, so a zigzagging/looping route (a threaded corridor) turned every enclosed pocket into a spot where the hover UI vanished — and the pocket reshaped with each zoom because Leaflet re-clips the path per view. Fixed with pointer-events: stroke (90 phantom grid points → 0 in a DOM hit-map, on-line hover intact). Also: a tapped Top Route Proposal now deselects when a ghost waypoint splits its corridor — anchorsAreWaypoints requires the anchors to be CONSECUTIVE waypoints, mirroring the reducer's insertMid un-force rule, so the ✕ badge and “Top Route Proposal” header can no longer outlive the corridor they describe.
2026-07-08

Forced-corridor threading — drop any waypoint on a diamond, get an explicit flag

Dropping a waypoint onto a route-based top proposal now threads the route through the whole corridor with an explicit forced-corridor flag in the canonical Selection, replacing the implicit coords-equal-anchors matching. All three drop scenarios work — dropping the END gives S…A→Z with the far anchor becoming the end, dropping the START gives AZ…E, and mid/path drops stamp the flag they already threaded — with anchor order chosen by whichever chain is shorter. Every spec break rule un-forces the pair: drag either anchor away, insert a mid between them, remove an anchor. The flag rides the URL as a compact ,f<proposalId> token (deep links re-resolve the live proposal and snap onto the corridor once proposals compute) and the in-app back/forward history; an edge-id snapshot keeps the forced geometry stable when live vote deltas reshape or retire the proposal. Verified live on nyc-walkways: threading, breaking, re-threading, two corridors coexisting (70-pt + 21-pt verbatim chains), URL restore, and history stepping.
2026-07-08

Block-graph redesign — absolute-vote heat, Voronoi junction cells, graph-first foot blocks, degenerate-block merging

The heatmap now shows total absolute votes (up + down — downvoted blocks read hot, not silent), and the Layer-2 block pipeline was redesigned end-to-end. Junction blocks are Voronoi cells at cluster centroids clipped to a max radius (no more stacked-disc gloops), with oversized single-linkage clusters split along their principal axis (worst NYC chain: 1,607 junctions / 483m). Junction capture went topological — both endpoints in clusters, same cluster or a ≤30m crosswalk — freeing the 62.8% of all NYC edges the old midpoint-≤12m rule swallowed, which is why Central Park rendered as node gloops. Foot blocks are graph-first: components severed at junction clusters, polygons buffered from exactly their member edges, membership shipped by construction. A new fixpoint merge pass absorbs degenerate blocks — the W 31st & PPS 100 LLC garage entrance now dissolves into the West 31st Street block — and a field-reported Times Square weld (corridor merges fusing Broadway + 7th Ave + three cross streets into one 404m block) tightened the junction-dissolve rule to single-neighbour junctions only. NYC re-baked: 3.3M edges 100% mapped, 235,769 blocks.

Aesthetic fixes — slimmer selection rings, and an incandescent tip for the heat ramp

Two visual fixes, verified live: the selected double border on top-proposal markers is now a true 2.25px contour of the outer shape on every marker kind — replacing the point pin's 3px inset and the route diamond's uneven hand-placed ≈3.5–4.2px one, so diamonds and pins carry identical-weight rings with more air around the glyph. And the heat display keeps resolving at the top of the scale: the intensity math was already logarithmic, but the block fill flat-topped its color ramp at heat 0.6 — on nyc-bikes every block from 46 to 617 votes (4,152 blocks, exactly the hottest parts of the map) painted one identical gold. Every ramp now extends past peak into a computed incandescent tip (white-hot on dark basemaps, ink-dark on light ones), stops respaced to 0/.35/.65/.85/1, the block fill spans the full heat domain with a heat-driven outline width, and the canvas hottest-edge accent strokes the tip — legend, canvas heatmap, proposal pins, and block fill all still agree. Round 2: heat then moved off the pin outline entirely — hot pins used to brighten their border, which is hover's channel, so everything hot looked hovered. Heat now renders as a solid glow ring: the pin's own shape stroked wide in the ramp color beneath the paper fill — a hard, fully-opaque band outside the hairline, no blur, no fade — leaving the outline to hover and selection alone. Round 3: pin colors are now PINNED TO RANKING — dense rank over the visible top proposals' vote counts, spread across the map's ramp, capped at peak (the incandescent tip stays the heatmap's) — so every top proposal wears its own hue; plus a slimmer ring and “No votes yet” empty-state copy.

Junction clusters, capture mapping, and the stale-heat guards

Round two on junction blocks, from live screenshots: intersections drew as stacked overlapping circles (a physical intersection is many OSM junction nodes — 94% of NYC's junctions have a neighbour within 24 m), band cutouts looked misaligned (bites from invisible sibling discs), and voted node blocks stayed dark on the heatmap. Overlapping discs now merge into one multi-node block per junction cluster (415,967 discs → 99,535 blobs, radius 12 → 9 m), and nodes get their own mapping rule: the bake's new junction-capture pass maps any edge midpoint within 12 m of a junction to that junction's block by graph distance — 5,351/5,351 midtown crossing stubs land in junction blocks, 0 perpendicular, 0 unmapped. The dark heatmap was a stale-cache class, not rendering: block ids renumber on re-bake under the same topology etag AND revision, so the boot painted a pre-re-bake IndexedDB votes body and deltas layered onto it — closed by an n_blocks/blocks_version guard on the votes cache, a blocks-mtime stamp in the graph-votes ETag, and a pid-unique tmp for the geojson writers (two pipeline runs interleaving one shared .tmp corrupted 300 MB of blocks mid-rebuild).

RBTP parity — mixed cluster fan-out, corridor drops, people-not-blocks vote counts, and a route ✕

Five requests bringing the route-proposal diamonds to full parity with the point pins. Diamonds now fan out with crowded point-pin clusters (one mixed grid; diamond clicks explode-before-select like the squares); dropping any waypoint — a dragged mid, a fresh path-drag ghost, or an exploded-proposal drag — onto a diamond threads the route through the WHOLE corridor, inserting its two anchors in whichever order gives the shorter prev→anchor→…→anchor→next chain, and the selected diamond carries the same [×] the matched point pins have (removes both anchors atomically). 2026-07-07

API latency fixes — kill the per-request DB tax, unblock the gevent hub

The per-endpoint dashboard exposed a shared floor under every API call: resolve_map's map lookup LEFT JOINed a full-table COUNT over 1.8M edge_votes rows on the f1-micro, per request — 320ms medians on endpoints whose real work is sub-millisecond. Fixed by splitting the map query (indexed per-slug count, or none for resolve_map) behind a 30s TTL cache with mutation invalidation; adding psycogreen + a real connection pool so one slow psycopg2 query no longer freezes every in-flight request on the gevent worker (the old shared singleton connection was only safe because the hub blocked); a per-instance 60s maps-list cache; and graph-votes 304s answered straight from Redis before ensure_loaded, so cold instances don't load a graph to say "unchanged". Verified locally: sub-ms warm endpoints, tests green, 32-greenlet concurrency harness clean. Prod deploy pending.

2026-07-05

MapLibre ↔ Leaflet position drift — zoom off-by-one + riding the zoom animation

The post-restyle “position drift” was two camera bugs between the renderers that now share the screen. Leaflet defines zoom against 256px world tiles, MapLibre against 512px — passing the zoom straight through ran the GL base map + block heat at exactly 2× Leaflet's scale, aligned only at the screen center (measured: 117 px vs 233 px for the same probe point). And during animated zooms Leaflet suppresses move events, freezing the GL map for 250 ms while pins glided. Fixed with a −1 zoom offset plus a zoomanim CSS-transition ride on the GL container using Leaflet's exact curve; verified sub-pixel in the live app.

Three-layer voting model — graph · blocks · route proposals

The edge/node graph stays the storage source of truth; procedural per-city blocks (median IoU 0.84 vs NYC planimetric ground truth) become the aggregation/display/interaction grain — votes deduped once per voter, block-scoped clear-then-cast in /api/vote so a block never holds + and − from one device; route proposals are now computed deterministically on the client (server Leiden engine removed). 2026-06-17

The mobile-Safari heatmap crash was the graph's own memory

"A problem repeatedly occurred" on phones (bikepaths and the other NYC street maps) wasn't the server, the subdomain routing, or vote-sync — those were ruled out one by one. The foot-aligned rebuild doubled the NYC graph to 3.3M edges, and the client decoded its 35 MB binary blob into ~497 MB of boxed JS tuples, over mobile Safari's per-tab budget. Backed the topology with flat typed arrays (coords/ends + CSR adjacency) read through accessors — ~497 MB → ~71 MB, off the object heap entirely.
2026-06-17

Unifying the icon-explode model — one cluster fanned out at a time

Crowded proposal icons fan out ("explode") into a grid so you can pick one from a stack. The state behind it was two overlapping spread maps merged on every render — built to keep several clusters open at once. Collapsed them into a single spread plus a lock flag, routed all cluster detection through one clusterAround() helper and collapsing through one collapseSpread(), and made a fresh fanout replace the open one — so exploding any icon set un-explodes the others.
