Three fixes in one pass: the stale-cache crash that loops mobile Safari on heatmap load, the concurrency limits that broke the app under multiple tenants, and the heatmap that vanished mid-zoom.

Backend + Frontend

1 · Stale-cache crash on heatmap load

Symptom

On mobile (iOS Safari) the app showed “a problem repeatedly occurred” on heatmap load — reproduced on the NYC e-bikes (station-network) map. That message is Safari’s crash-reload loop: the page throws, Safari reloads, it throws again.

Root cause

  • The heatmap is painted by indexing per-edge / per-node vote arrays returned by /api/graph-votes against the graph topology the client holds. Topology is cached aggressively (IndexedDB + a day-long HTTP max-age); votes refresh every few seconds.
  • When the two disagree on dimensions — a stale cached topology with a different node/edge count than the fresh votes (after a graph rebuild, or when the version probe fails so the cache-busting URL is skipped) — the render indexes past the end of the arrays, or the binary topology decoder allocates garbage from a corrupt blob. Either throws, and there was no error boundary, so the whole React tree died → Safari loop.

What changed

  • Server stamps the topology dimensions onto the votes (n_edges, n_nodes, topology_version) so the client can detect a mismatch instead of trusting that the arrays line up. (server/app.py · _build_graph_votes_body_locked)
  • Client validates before painting. votesMatchTopology() compares the stamped dimensions to the held topology; on mismatch it refetches the topology fresh — bypassing both the IndexedDB and the HTTP cache (cache: "reload") — rebuilds the indices, and only then applies the votes. If it still can’t reconcile, it clears the persisted cache and bails rather than paint a crash.
  • Hardened the binary topology decoder. decodeTopologyBin() now validates the GTB1 magic + the exact byte length before allocating, and clamps out-of-range node indices — a corrupt/truncated cached blob throws cleanly and falls back to a fresh fetch instead of OOM-ing the tab. buildEdgeIndex() no longer dereferences a missing node.
  • Added a React error boundary around the map. The first render crash in a session clears the (usually poisoned) graph cache and reloads once; a second crash shows a manual “Reload the map” fallback instead of looping. This is the definitive backstop for “a problem repeatedly occurred”, whatever the trigger.

Backend

2 · Concurrency — safe under >1 instance / many tenants

Symptom

The app crashed when more than one tenant used it at once, and couldn’t safely scale past a single Flask instance.

Root cause

  • Production runs a single gevent gunicorn worker (the NYC graph is too big to duplicate across workers). gevent greenlets don’t preempt on CPU, so the seconds-long, pure-Python build of the vote arrays (~2M NYC edges) froze the whole worker — concurrent tenants’ requests (and the health probe) stalled behind it. Worse, N concurrent first-requests for the same map each rebuilt the same body in series (head-of-line blocking).
  • The in-memory _vote_cache was an unbounded dict: every (map, mode) ever requested kept its full JSON body resident forever — a steady memory leak that OOM-crashes a multi-tenant server with many maps. Its invalidation also only popped the bare slug, never the per-mode <slug>:<mode> keys it actually stored.
  • The voter read-modify-write was guarded only by a per-process threading.Lock — meaningless across instances/workers, so two near-simultaneous votes from one voter could double-apply.

What changed

  • Bounded LRU vote cache. _vote_cache is now a capped OrderedDict (VOTE_CACHE_MAX, default 64) guarded by a lock — memory stays flat no matter how many tenant maps exist.
  • Correct, mode-aware invalidation. _invalidate_vote_cache(slug) drops the bare slug and every <slug>:<mode> variant; wired into the vote path, the pub/sub delta listener, and the graph-reload re-snap.
  • Single-flight on the expensive build. A per-cache-key lock means one greenlet builds the arrays while the rest wait and take the result — killing the head-of-line stampede that stalled the worker under concurrent tenants.
  • Cross-instance voter lock. vote_store.voter_lock() is a short Redis SET NX lock keyed by (slug, device) that serializes a voter’s read-modify-write fleet-wide; it auto-expires and fails open so a vote never hangs on Redis. Combined with the bounded shared-state design, this is what makes running more than one instance safe.

Files touched

  • server/app.py — bounded LRU + _vote_cache_get/put, _invalidate_vote_cache, _build_lock_for single-flight, voter_lock wiring
  • server/vote_store.py — voter_lock() cross-instance Redis lock
Frontend

3 · Zoom overhaul — heatmap scales instead of vanishing

Symptom

The heatmap disappeared while zooming and only snapped back after the zoom finished.

Root cause

  • The heatmap is a hand-managed <canvas> in a custom Leaflet pane. On zoomstart the canvas was cleared, and it was only repainted on zoomend — so for the whole ~250 ms zoom animation it was blank. Unlike Leaflet’s own tile / canvas renderers, it never rode the zoom animation’s transform.

What changed

  • Stopped clearing the heatmap canvas on zoomstart — the existing bitmap stays up.
  • Gave both canvases the leaflet-zoom-animated class so Leaflet’s zoom-animation CSS transition applies to their transform.
  • Added a zoomanim handler that sets each canvas’s transform to where its top-left geographic corner lands at the target zoom, scaled by the zoom ratio (getZoomScale + _latLngToNewLayerPoint — the exact mechanism L.Canvas uses). The browser tweens it, so the heatmap glides and scales with the map. zoomend then repaints crisply at the new resolution and line widths.
  • The draw state (zoom + top-left lat/lng) is recorded at the end of every paint so the animation transform is always anchored to the right geography.

Files touched

  • client-react/src/components/GraphLayer/GraphLayer.tsx — drawStateRef, leaflet-zoom-animated class, handleZoomAnim, zoomstart no longer clears the heatmap

+      }
+    }, 12000);
+  }
+
+  componentWillUnmount(): void {
+    if (this.healthyTimer) window.clearTimeout(this.healthyTimer);
+  }
+
+  componentDidCatch(error: Error, info: ErrorInfo): void {
+    console.error("Render crash caught by ErrorBoundary:", error, info.componentStack);
+
+    let alreadyTried = false;
+    try {
+      alreadyTried = sessionStorage.getItem(RECOVERY_FLAG) === "1";

+    }

+@contextlib.contextmanager
+def voter_lock(redis_client, slug: str, device_id: str,
+               timeout: float = 5.0, ttl: int = 10):
+    """Serialize one voter's read-modify-write on a map ACROSS Flask instances.
+
+    The app's per-process threading.Lock only orders votes within a single
+    worker; run more than one worker/instance and two near-simultaneous votes
+    from the same voter can each read the same prior direction and double-apply
+    (inflating the count, or leaving a stuck toggle). A short Redis SET-NX lock
+    keyed by (slug, device_id) closes that race fleet-wide.
+
+    Best effort: the lock auto-expires (ttl) so a crashed holder can't wedge a
+    voter, and if Redis is unavailable we proceed anyway (the per-process lock
+    still holds) — a vote must never hang on the limiter. Yields True when the
+    cross-instance lock was actually held, False when we fell open."""
+    key = f"votelock:{slug}:{device_id}"
+    token = os.urandom(8).hex()
+    acquired = False
+    try:
+        deadline = time.monotonic() + timeout
+        while True:
+            if redis_client.set(key, token, nx=True, ex=ttl):
+                acquired = True
+                break
+            if time.monotonic() >= deadline:
+                break  # contended past the timeout — fall open, don't block
+            time.sleep(0.02)  # gevent-patched: yields the hub
+    except Exception as e:
+        logger.warning(f"[VOTELOCK] acquire failed for {key}: {e}")
+    try:
+        yield acquired
+    finally:
+        if acquired:
+            try:
+                # Delete only if the value is still our token, so we never clear
+                # a lock another instance acquired after ours expired.
+                if redis_client.get(key) == token:
+                    redis_client.delete(key)
+            except Exception:
+                pass
