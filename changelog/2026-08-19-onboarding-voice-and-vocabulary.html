The wall asks for a need, not for a volunteer

2026-08-19 · branch main
A vote type is a need, not a shift somebody signs up for The mark goes down on a decision, not on a sighting Ten vote types leave nyc-tactical The arrow, everywhere it was visible VerificationChecklistFull diff

Three notes from the owner on the first-run wall, and one of them reverses a decision this flow was built around. The tiles stop translating a vote type into a job the reader would do and name the NEED instead — "This unused patch of land needs flowers…", not "I'd put flowers where this bed is bare dirt…" — across nyc-tactical and four other maps' walls. The local "don't ask again" mark stops being written when the wall APPEARS and waits for the visitor to decide: a first vote, or "just take me to the map". Ten vote types leave nyc-tactical's vocabulary with their tiles; none of them carried a single vote, here or in prod, and prod is untouched pending sign-off.

COPY · THE MAIN NOTE

A vote type is a need, not a shift somebody signs up for

Symptom

Every tile on the opening wall translated its vote type into an ACTION THE READER WOULD TAKE: "I'd put flowers where this bed is bare dirt…", "I'd send our run this way…", "I'd chalk the crosswalk this corner should have…". The first screen of the app opened by asking a stranger to volunteer for a shift.

Root cause

  • The phrasebook's stated voice rule was FIRST PERSON on every line, without exception — "every line carries an I, a my, an us or a me". For a complaint ("I trip on this sidewalk every single time…") that is exactly right. For a vote type that names a deed — flower-bomb, chalk, adopt, repaint — the only first-person sentence available is the one where the speaker does the deed, so the rule itself manufactured the offer of labour
  • The derived tier had the same shape hard-coded for the volunteering verbs: run / organize / chalk / adopt / clear / sweep / shovel / water / repaint all produced I could <do it> here…, so every custom map inherited the defect too

What changed

  • The rule is inverted and stated first in the file: a need, never an offer of labour. "This unused patch of land needs flowers…" is the same vote type, the same cast, and a sentence somebody actually thinks. Anything shaped I'd <verb>… is now named in the header as the smell to check before adding a line
  • First person is demoted to a preference: personal where the need is personal ("My street is too hard to cross…"), plain statement where the need belongs to the street ("Cars drive too fast here…"). 11 nyc-tactical tiles rewritten to the owner's own copy
  • The same sweep applied to the other maps' walls: 10 further labels — Add tree, Plant trees, Create a tree pit, Create a community garden, Street redesign, Improve school crossing, Water the street trees along here, Weed and mulch this median, Add greenway connection, Highway
  • The derived branch says Somebody needs to <x> here… instead of I could <x> here…, so a map authored after this file obeys the rule without anybody writing a line for it
  • I'd ride this route if it had a lane… and I'd walk this whole way under trees… are deliberately LEFT: using the thing being asked for is a need, not labour. The test below draws that line explicitly rather than banning the I'd opening wholesale

FIRST RUN · REVERSES A PRIOR DECISION

The mark goes down on a decision, not on a sighting

Symptom

The local "don't show me again" suppressant was written THE MOMENT THE WALL APPEARED. Being shown a welcome screen and walking away from it counted as having been onboarded.

Root cause

  • That was a deliberate earlier choice, for a real reason: a reload is a second map open, so without an early write the visitor who refreshes gets the wall twice. It bought reload-safety by spending the visitor's one first run on a screen they had not read
  • It also made the wall un-resumable in the honest sense — the flow could conclude "done" about somebody who had made no choice at all

What changed

  • The wall-shown effect is deleted. Exactly two writes remain: the done step (a first vote landed) and handleDismiss ("just take me to the map", the coach's ×, Escape) — the two things that mean the visitor decided
  • Reload mid-flow resumes. The pick goes into the canonical Selection, which writes it to the URL (?vt=), so picked is true on the first render after a reload and the step derives to start / end / cast. Verified live: reloading on ?vt=Adopt+and+tend+this+tree+bed came back to the coach reading "A tree bed near me needs love… / Tap the map on the spot you mean.", no wall
  • Reload ON the wall brings the wall back, which is now the intended answer — nothing has been decided yet. It survives because the visitor probe's answer is cached in sessionStorage for the length of the visit, so the reload never re-asks the server (which would say "visited" and hide it)
  • The residual is documented at the effect rather than papered over: close the tab and return in a new session and there is no wall, because /api/visitor recorded the first open and sessionStorage is gone. Only the LOCAL mark moved — making the whole thing wait for a decision means the endpoint recording on the cast instead of on the open, a different change to a different layer
  • The three doc comments that asserted the old rule — firstRun.ts's header, its SUPPRESS_KEY note, and state.ts's MAP OPEN trigger — are corrected, because each was load-bearing for anyone reading the flow

VOCABULARY

Ten vote types leave nyc-tactical

Symptom

The wall carried tiles for a snow-only observation, three that recruit other people's children, a family of group rides / runs / tours, a community fridge and a snowbank crossing.

Root cause

  • The wall is built from the map's REAL vote types (tiles.ts reads /api/maps/<slug>), so a tile cannot be removed without removing the type — which is the correct coupling: a slip that cannot cast is worse than no slip
  • Seasonal types (Chalk the sneckdown outline, Shovel out this crossing) read as broken for the nine months they do not apply

What changed

  • Removed locally with server/manage_vote_types.py remove — the CLI, not raw SQL, so the read-back check runs and the target database is printed on every call: 25 → 15 types
  • The 11 phrasebook entries for the retired labels are deleted outright rather than left orphaned
  • Nothing was destroyed. All ten carry ZERO votes, in local and in prod alike — so no rebuild_redis_for_map pass was needed and no vote data was at risk. The count is in the sign-off table below because the owner asked to see it before agreeing, not because it turned out to be non-zero
  • Prod is untouched, per the brief. Eight of the ten are already absent there (the 2026-08-14 24→18 trim took them); the two prod still authors are Host a community fridge and Shovel out this crossing
