Unifying the icon-explode model — one cluster fanned out at a time

2026-06-17 · branch fix/unify-voting
1 2 VerificationChecklistFull diff

Crowded proposal icons fan out (“explode”) into a grid so you can pick one from a stack. The state behind that was two overlapping maps merged on every render — built to keep several clusters open at once. This collapses them into a single spread (plus a lock flag), routes all cluster detection through one helper, and makes a fresh fanout replace the open one — so only one icon set is ever exploded at a time.

React / Leaflet client

1 · Collapse the two-map spread state into one

Symptom

Crowded proposal icons “explode” (fan out into a grid) so you can pick one from a stack. The old model kept two overlapping spread maps — a lockedSpread and a transientSpread — that were merged into a union on every render, deliberately so that several clusters could sit fanned out at once. That made the desired behavior (“only one cluster open at a time”) impossible and spread the bookkeeping across two pieces of state, two refs, a union useMemo, and a mirror effect.

Root cause

  • lockedSpread (a box was selected → persists, no timer) and transientSpread (hover/tap → snap-back timer) only ever differed in whether a timer was running. Their position maps were identical in structure, and the render only ever read their union (spreadPositions). The two-map split existed solely to allow multiple simultaneous fanouts.
  • Because both spreadCluster and the locked-promotion path merged into the existing maps (new Map(transientSpreadRef.current ?? []), then merge transient into locked), exploding a second cluster added to the open set rather than replacing it.

What changed

  • Replaced lockedSpread + transientSpread (state) and their two refs with a single spread state, one spreadRef, and a boolean spreadLockedRef — “locked” is now just a flag on the one open spread, not a separate map. The union useMemo and its mirror effect are gone.
  • Added one applySpread(next) helper that sets the state and mirrors the ref in lockstep (the hot-path hit-test proposalIconAt reads the ref every drag frame), so no call site can update one and forget the other.

Files touched

  • client-react/src/components/GraphLayer/GraphLayer.tsx — spread state → single map + lock flag + applySpread()
React / Leaflet client

2 · One cluster fanned out at a time + DRY cluster detection

Symptom

Requested behavior: exploding one icon set should un-explode any other — only one set fanned out at once. Separately, the “is there a crowded stack here?” distance test was copy-pasted in three places (the path/drag exploder, the browse-click handler, and once inline for the anchor cluster), each re-deriving the same radius math.

Root cause

  • spreadCluster merged into the open transient spread, and selecting a box merged transient into locked — so a second fanout coexisted with the first by design.
  • Three sites filtered placed by CLUSTER_RADIUS_PX with their own copy of the squared-distance loop.

What changed

  • Replace, don’t merge. spreadCluster now builds a fresh new Map() and calls applySpread(next), so fanning out any cluster automatically collapses whatever was open. Exploding set B un-explodes set A for free.
  • Selecting a box just flips the lock. Picking a fanned-out icon sets spreadLockedRef.current = true and cancels the timer (the position map is unchanged, so no re-render) instead of rebuilding a merged locked map. A lone, non-fanned icon calls collapseSpread().
  • One cluster-detection helper. Extracted clusterAround(anchor) — the 2+ icons within CLUSTER_RADIUS_PX of a screen point — and routed both the path/drag exploder and the browse-click handler through it.
  • One collapse path. collapseTransient + collapseAll collapsed into a single collapseSpread() (clear timer → unlock → clear spread → schedule class clear) shared by the snap-back timer, pan/zoom, and deselect; clearSpreadTimer() replaces the duplicated pauseSpreadTimer.

For you

Manual checklist

  • Open http://localhost:3000/m/nyc-walkways at a zoom where several proposal icons stack, and tap a crowded stack — it should fan out into a grid.
  • With one cluster fanned out, tap a different crowded stack — the first should snap back as the second fans out (only one open at a time).
  • Tap one of the fanned boxes — it should select (start a route / open the modal) and the spread should stay put (locked, no snap-back) until you pan, zoom, or clear the selection.
  • Let a fanned cluster sit untouched — it should snap back after ~2.2s; hovering one of its icons should pause that countdown.
  • Drag a waypoint over a crowded stack — it should fan out so you can drop on a specific icon, and dragging onto a different stack should re-fan the new one.
  • On a station map (/m/e-bikes-3) confirm station markers still select/deselect normally (no spread there).
