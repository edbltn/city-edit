Layer-anchor failsafes — the map can no longer stay misaligned

2026-07-15 · branch fix/unify-voting
1 VerificationChecklistFull diff

A screenshot pair showed the white route layer sitting offset from the block heat — differently at each zoom — then healing on its own. The projection math was fine; the re-anchor chain after zoom animations was fragile. Five failsafes now make every layer converge back onto the map no matter which link drops.

Frontend

1 · Transient layer misalignment — and why it could persist

Symptom

Screenshots at two zooms showed the white route/highlight layer offset from the block heat + base map underneath, with a different offset at each zoom. The drift self-healed on the next interaction — the signature of a stale frame, not bad projection math.

Root cause

  • Two renderers share the screen: Leaflet (SVG routes, pins, the highlight canvases) and MapLibre GL (base map + block heat). Both “ride” Leaflet's animated zoom with a CSS transform hack, then re-anchor afterwards — and both re-anchors hang off a fragile chain: MapLibre's camera is only re-synced by Leaflet's final move event, and the canvas repaint is scheduled on a bare requestAnimationFrame.
  • Any dropped link leaves a layer painted for the OLD camera: a zoomend that arrives without a final move, an rAF that never fires (rAF freezes entirely in hidden/occluded windows — a known trap on this project), or a repaint that lands mid-animation and bakes inconsistent transforms into the bitmap (WS deltas and route-highlight events can trigger paints at any time).
  • On block maps the exposure was worse: drawStateRef — the record of which camera the canvas bitmap was painted at — was only ever written on the no-blocks code path, so on block maps (exactly the maps in the screenshots) the zoom-anim ride and any drift detection flew blind.

What changed

  • Never paint mid-zoom. redraw() and redrawHoverHighlight() bail while a zoom is in flight — a paint against a mid-animation pane transform lands misaligned and stays that way if the zoomend repaint drops. zoomend always schedules a redraw, so deferring loses nothing.
  • Always record the painted camera. drawStateRef is now stamped at the top of every paint, before any early return — block maps included — so the ride and the failsafe below always know the bitmap's true anchor.
  • Timer backstop for the rAF repaint. scheduleRedraw() arms a 200 ms setTimeout alongside the rAF; whichever fires first wins and cancels the other. Timers are throttled but still run in hidden windows — rAF does not.
  • Drift check on every move frame + visibility restore. ensureAnchored() compares the bitmap's painted zoom to the map's zoom (a number compare); on mismatch outside a zoom it logs [topo] anchor drift… and repaints synchronously — not via the rAF path that already failed once.
  • MapLibre reconcile(). On zoomend, moveend, and visibility restore: clear any leftover ride transform, re-jump the camera unconditionally (no longer trusting that a final move preceded zoomend), and triggerRepaint() to force one GL frame. Each step is a cheap no-op when nothing drifted.
