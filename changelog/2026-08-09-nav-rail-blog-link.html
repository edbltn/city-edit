A blog link, and a header with room for it

2026-08-09 · branch main

A blog link, and a header that had room for it. The map header’s four meta buttons — Feedback, About, Donate and a stray How it Works — collapse into a NavRail: two enclosed segments of icon buttons, things to read then things to do, shared with the landing page. The glyphs are drawn to the app’s own grid (square caps, mitered joins, every mark built from a rectangle) rather than imported, and everything goes icon-only except Donate, which keeps its word and the map’s accent. The controls people actually came for are untouched. The right-hand column drops 395px → 294px, which exposed and then closed a pre-existing overflow: the desktop layout had a hard ~1353px floor, because the legend was flex-shrink: 0 and could never let its address ellipsise.

THE PROBLEM

Five links wanted the same row

Symptom

The map header carried Feedback, About and Donate as full-width text buttons, with How it Works sitting a row below among the vote controls. The blog had to go somewhere, and a fourth label in that row was not an option — the meta links were already as loud as the controls people come to the map to use.

Root cause

  • Every one of them was a .btn-header: same size, same weight, same border as each other AND as the Clear button next to the vote controls. Nothing in the bar said which things were the map and which were the website
  • How it Works was in .actions-group — the row-2 cell that otherwise acts on the current selection — purely to stop that row collapsing to zero height before a selection existed
  • Together they set the header's right-hand column at 395px, which the legend then had to fit alongside

What changed

  • One shared NavRail: two enclosed segments of icon buttons — How it Works · Blog · About | Feedback · Donate
  • Grouping is carried by enclosure, not by a divider or a heading: the first box is things to read, the second is things to do. How it Works belongs in the first, so it moves out of the selection row
  • That row now legitimately stays empty until there is a selection — the fixed grid-template-rows was always what held it open, not the button
  • Right-hand column: 395px → 294px

THE ICON SET

Drawn to the app's grid, not imported

Symptom

Icon-only buttons need icons, and the obvious move — pull in Lucide or Feather — would have put rounded caps and 2px strokes on a 24px grid next to a monospace, zero-radius, hairline interface.

Root cause

  • The app already has a drawing language: CheckIcon is explicitly square-capped and mitered “unlike the rounded unicode ✓”, and the logo is letters set in a crossword grid of squares
  • A pack's icons are internally consistent with each other, which is exactly what makes them read as a foreign body — they are consistent with the wrong thing

What changed

  • Five glyphs on one skeleton: a 24 grid, 1.75px strokes, square caps, miter joins, and every mark built from a rectangle on that grid
  • ? and i are set in the logo's lettered box, so the two informational marks read as a pair; the article and the speech bubble are the same rectangle carrying different contents
  • The heart is the one curve in the set — which is what makes Donate the glyph the eye lands on first
  • The article's image block is filled rather than stroked: at the 15–18px these render at, a 6×5 stroked box is all outline and silts up into a grey smudge

HIERARCHY

Sizing by how much each thing matters

Symptom

Decluttering by shrinking everything equally just makes a smaller undifferentiated row. The bar needed to say what it is for.

Root cause

  • The controls that do the work — the Map and Vote selectors, the Cast −/+ buttons — were the same visual weight as a link to an external website
  • Donate is the one meta item with something to ask for, and it was one of three identical siblings

What changed

  • The working controls are untouched: full --control-height, full labels, and Cast keeps its 44px buttons
  • Everything in the rail goes icon-only — except Donate, which keeps its word and the active map's accent fill, so one item in the quiet half still reads first
  • Below 1080px Donate sheds its label too and joins the grid of squares; the width that frees goes to the Map/Vote selectors, which is where it is worth spending
  • Clear deliberately keeps its text: a bare × sitting beside − and + reads as an operator
  • Tooltips are hover-only (@media (hover: hover)) so a tap never leaves one stuck open; aria-label carries the name regardless

BUG FOUND EN ROUTE

The desktop header had a hard 1353px floor

Symptom

Measuring the new rail at 1300px showed the topbar overflowing its viewport by 53px, with Donate clipped at the edge. It was not the rail: the same measurement against the pre-change markup put the floor at ~1454px.

Root cause

  • .topbar-legend was flex-shrink: 0, and it holds the widest thing in the bar — a 250px address slot
  • So the desktop layout could never be narrower than legend + selectors + links. Every window between the 1080px breakpoint and ~1353px scrolled sideways
  • The truncation machinery already existed and was already commented at length — it was just scoped to the ≤1080 block, so above the breakpoint the address could never ellipsise

What changed

  • flex-shrink: 0 → min-width: 0 on the legend, and .legend-item-coords { min-width: 0 } promoted out of the ≤1080 block so it holds at every width
  • The address now ellipsises above 1080 exactly as it already did below it
  • The rail is pinned with justify-self: end so its right edge stays flush with the legend's whichever of the rail / Cast+Clear happens to be wider — they currently tie almost exactly, and relying on that tie would be luck

LANDING PAGE

One nav instead of two

Symptom

The landing page had About / Feedback / Donate as footer links. Adding Blog there would have made four links at the bottom of a page whose entire job is picking a map.

Root cause

  • A footer is where links go when there is nowhere better, and on this page there was somewhere better — the header is mostly empty space either side of a centred logo

What changed

  • The same rail, pinned top-right of the header; the footer drops to the copyright line alone
  • Below 720px it unpins and returns to the column under the tagline — in the corner it would clip the logo's top-left square at that width
  • It is last in the DOM for that reason: pinned, position is cosmetic, but in the column source order is the visual order, and so the focus order
  • No How it Works here — that glyph describes this map's controls and has nothing to say on the picker, so it is dropped rather than shown inert
  • Donate keeps its label at every width on this page: the 1080px rule exists because the map header is fighting for room, and this page is not

Verification

What was run

  • Measured, not eyeballed: at 320 / 360 / 390 / 430 / 560 / 768 / 900 / 1024 / 1100 / 1200 / 1300 / 1440px the document's scrollWidth equals the viewport at every step — no horizontal overflow at any width.
  • The rail's right edge and the legend's right edge come out identical at every one of those widths (e.g. both 370 at 390px, both 1280 at 1300px).
  • The 101px saving is a measurement, not an estimate: the pre-change markup was rebuilt in the live DOM and measured at 395px for the old column against 294px for the rail.
  • .topbar does still report internal overflow below 768px — traced to the closed .mode-dropdown panel, which is pre-existing, absolutely positioned, and does not reach the document.
  • Driven in the running app: hovering a glyph shows its tooltip (How it works, Blog), and clicking the ? opens the How it Works modal from its new home in the rail.
  • Link attributes read back from the DOM — all four anchors carry target=_blank, rel="noopener noreferrer" and an aria-label, with Blog resolving to https://sphericalharmonics.substack.com/.
  • Responsive behavior was verified in iframes rather than by resizing the window — the window would not resize, and short iframes silently triggered the (max-height: 500px) landscape query, which collapses the legend and made an early reading look broken. Frames were then sized past 500px tall.
  • The landing rail was checked at 1000px (pinned top-right) and 390px (in-column under the tagline).
  • npx tsc -b clean and npm run build succeeds — Vite dev never type-checks, so this is the only thing between an edit and a broken client build.
  • Committed as a partial stage: another session is mid-flight in TopBar.tsx (the Vote → Proposals selector change), so only this workstream's hunks were staged and git show :…TopBar.tsx was read back to confirm their edit was neither committed nor lost from the working tree.
For you

  • Open http://localhost:3000/m/nyc-walkways — expect two small boxes of icons at the top right: [?] [▤] [i] then [▭] [♡ Donate], with Donate in the map's accent.
  • Hover each glyph and confirm the tooltip names it; click [?] and confirm the How it Works modal still opens.
  • Click the newspaper glyph and confirm it opens sphericalharmonics.substack.com in a new tab.
  • Drag the window narrow and back — watch the Donate label drop away around 1080px and the start/end address ellipsise instead of the bar running off the right edge. Nothing should scroll sideways at any width.
  • Place a start and end and confirm the Cast −/+ and Clear controls appear on the row below, unchanged in size.
  • Open http://localhost:3000/?landing=1 — rail top-right, and the footer now shows only the copyright line. Narrow past 720px and confirm it moves to under “Redraw your city.”
  • On a phone, check the icon buttons are comfortable to hit — they are 32px wide at ≤1080 and 29px at ≤400, which is the one judgement call here worth a second opinion.
