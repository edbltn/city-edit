Three fixes to Top Proposals: a pin now takes real support (>100 net votes, both point and route families); every modal badges the vote types that are CURRENT top proposals for what it shows (square = point, diamond = route fully inside the selection); and route corridors are now grown ROUTING-CONSISTENTLY — an extension either keeps the segment a shortest path or pins a ghost waypoint (max 3), and the whole waypoint chain lands in the URL, so a shared top-proposal link keeps routing into its corridor long after the proposal itself has churned away.

INFRA / JOBS

One OOM was failing every remaining map in the run

Symptom

No preview existed for nyc-proposals (the Landing card 404'd outright), and philly-trees / philly-walkways served an 11 KB screenshot of the "Loading…" splash dated 2026-07-09. Meanwhile the daily job reported a green 1/1 complete every single morning.

Root cause

  • capture.py drove all 13 maps through ONE shared Chromium page. Memory grew across sequential navigations of these heatmaps until the 2Gi container OOM'd — and because the page was never recreated, every map after the crash died instantly with Page.goto: Page crashed
  • The crash point walked BACKWARDS as the heatmaps grew: map 12 (philly-bikes) on 07-19 and 07-22, map 1 (nyc-bikes) by 07-30, and mid-capture on map 1 by 08-02. Recent runs were capturing nothing at all
  • nyc-proposals is 5th in the capture order and was only renamed from nyc-crossings on 07-30 — by which point the crash had already reached map 1, so it was NEVER captured once under its current slug
  • No baked fallback exists for it either (client-react/public/previews has no nyc-proposals.png), so nginx's @baked_previews could not cover the gap and the card 404'd

What changed

  • A throwaway browser per map (capture_map): bounds memory regardless of how heavy the maps get, and contains a crash to the map that caused it instead of failing the other twelve
  • --disable-dev-shm-usage — containers give /dev/shm only 64 MB, which Chromium reports as an opaque renderer crash
  • Job sizing follows the new shape: 8Gi (nyc-trees still crashed the renderer at 4Gi even alone in the container), timeout 1800s (300s could not fit even the old shared-page run, which took ~5 min), and max_retries 0 since capture failures are deterministic — a retry only doubled a long run

CORRECTNESS

Publishing a screenshot of the loading spinner over a good preview

Symptom

philly-trees and philly-walkways were frozen on a picture of the app's "Loading…" splash — 11,011 bytes against ~950 KB for a real render — and had been since 2026-07-09.

Root cause

  • On canvas-check timeout capture.py printed "capturing anyway" and published the result regardless, so a slow cold load overwrote a good preview with a spinner
  • The canvas-content check CANNOT gate publication on its own: it waits for a non-transparent pixel on a Leaflet canvas, and maps with zero votes never paint heat. All three philly maps have 0 nonzero edges out of 1,177,930 — philly-bikes only looked fine because its basemap had painted by the time the 30s check gave up
  • Nothing ever overwrote the bad image afterwards because the OOM cascade meant the run never reached maps 12 and 13 again

What changed

  • Wait for the .map-bootstrap splash to clear (present-or-visible check, 60s) — the one reliable "app is past loading" signal that does not depend on vote data
  • MIN_PNG_BYTES = 60_000 publish gate: a 1400×900 basemap is never 11 KB, so an unpainted render is refused rather than overwriting a good preview
  • Passcode-gated maps are skipped entirely — nyc-ebike-charging has requiresPasscode: true and can only ever render an unlock prompt; a public preview would defeat the gate
  • Preset maps fall back to their slug route if the subdomain does not load

OBSERVABILITY

Why nobody noticed for six weeks

Symptom

Every execution since at least 2026-07-19 reported ✔ 1/1 complete. The last fully-healthy run was 2026-07-22.

Root cause

  • Each map was wrapped in a per-map try/except that printed to stderr and moved on, and main() never inspected the outcome — so a run where 12 of 13 maps failed still exited 0
  • Cloud Run only surfaces the process exit code, so the scheduler, the console, and any alerting all saw a healthy job

What changed

  • main() now tracks captured/failed, prints Done. Captured N/M, and exits non-zero when any map fails — a partial run shows up RED
  • The very first post-fix run proved the point: 11/13 with a red X, which is exactly how the two genuinely-broken maps got found and fixed
  • sync_to_gcs no longer swallows its own exceptions — a failed upload used to count as a success

Verification

What was run

  • Root cause reproduced from the job's own logs: the 2026-07-22 run shows Out-of-memory event detected in container followed by 12 consecutive Page.goto: Page crashed errors — and the Cloud Run retry restarted at map 1 and OOM'd again immediately.
  • The crash point demonstrably walked backwards: canonical bucket objects are dated 07-22 for most slugs, 07-30 for nyc-bikes alone, and 07-09 for philly-trees/walkways.
  • The junk-preview mechanism confirmed by data, not inference: all three philly maps report 0 nonzero edges out of 1,177,930 via /api/graph-votes, so the canvas check can never pass there.
  • New code exercised locally against prod BEFORE building the image: philly-trees went 11,011 → 955,310 bytes (a real Philadelphia street network, not a spinner) and nyc-proposals captured at 1,209,969 bytes.
  • The reject path was tested rather than assumed — with MIN_PNG_BYTES monkeypatched to 1e9 the run refused to write the file, printed Failed: philly-trees, and exited 1.
  • Deploy discipline: prod DB backed up first (~/city-edit-prod-backups/20260802-221945/prod-full.dump, 27 MB), and terraform applied with -target — plan showed 0 to add, 1 to change, 0 to destroy, touching only memory/timeout/max_retries.
  • First post-fix prod run: 11/13, red X — no cascade, and the honest exit code immediately surfaced the two real failures (nyc-trees renderer crash at 4Gi; nyc-ebike-charging is passcode-gated).
  • Final prod run after 8Gi + private-map skip: Done. Captured 12/12, job green, and all 12 public /previews/*.png serve real renders (nyc-proposals 1,209,835 b; philly-trees 956,372 b). nyc-ebike-charging still 404s — correct, it is private.
