### Behaviour worth watching after this one

`a03f125` adds two response headers to `/api/graph-votes` (`X-Vote-Rev`,
`X-Vote-Rev-Current`) and a CORS `Access-Control-Expose-Headers`. Clients use
them to notice they were served a revision-stale snapshot and refetch once.
Old clients ignore unknown headers, so the change is backward compatible — but
it is the only server-side change in this batch, and the only one that can
affect cache behaviour.

### Licence (`6532b95`) — ships no bytes

Listed above with the rest, but it is worth being exact: this commit changes
nothing in the running image.

| File | Reaches the image? |
|---|---|
| `LICENSE` | No — repo root; no Dockerfile copies it |
| `README.md` | No — same |
| `client-react/package.json` | Enters the builder stage, but `"license"` is metadata; the bundle is unchanged |

`Dockerfile.overlay` ships only `/app/dist`, `server/*.py`, `server/data/`, and
the two `deploy/` configs. So there is **no prod verification step** for this
commit — nothing to curl, nothing to look at. Its only build-side effect is
busting the `client-builder` npm cache layer, which costs a rebuild and nothing
else.

The licence is therefore live the moment the repo is pushed, not when this
deploy lands. The two are independent.

**Follow-up, not a blocker.** Nothing in the served app points at the source:
`grep -rn "github\.com" client-react/src client-react/index.html client-react/public`
returns zero hits. AGPL §13 obliges *people who modify and then publicly run*
City Edit to offer their users the Corresponding Source — as the copyright
holder running unmodified code, Eric isn't bound by it against himself, so this
does not gate the deploy. But a source link is what makes the copyleft
enforceable in practice, and the app already renders an attribution control
(`mapStyles.ts`, `MapView.tsx`) that is the obvious home for one.

### What this overlay cannot ship

`dce24ab` and `c38f289` are place-label work, and the overlay ships their

`build_place_labels.py` writes during the *full* image build (it reads
`source.osm.pbf`, deleted in the same `RUN`). `Dockerfile.overlay` copies only
`client-react/`, `server/*.py`, `server/data/` and `deploy/` — it never runs
that builder and never touches `osm_data/`.

deliberately out of scope for a code-only overlay.

# Addendum — the place labels need a SECOND overlay

**The code overlay above is not sufficient for the map-label work.** It ships
the client and `server/*.py`, but the POI layer reads a per-city artifact,
`osm_data/<city>/places.pmtiles`, that the regular `Dockerfile` builds inside
the graph `RUN` — a layer no overlay runs. Ship code alone and the feature is
silently inert: `cities.py` stats a file that isn't there, reports
`placesVersion=null`, and the client adds no layer at all. No error, no
console warning, just no business names.

That null-guard is deliberate (a city built before the artifact existed must
not request an archive that 404s on every pan), which is exactly why this
failure is quiet and worth writing down.

## Why these artifacts can be staged from a local build

Unlike the block artifacts, `places.pmtiles` carries **no edge ids and no
topology stamp** — every feature is a lat/lon, a name, a category and a reveal
zoom, read straight out of `source.osm.pbf`. There is nothing for it to be out
of step *with*, so it does not have to be baked against the base image's own
graphs the way `edge_blocks` does, and shipping it needs no full graph rebuild
(which would shift every edge id and force a vote resnap).

Staged: `.places-staging/<city>/places.pmtiles`, 8 cities, **3.8 MB total**
(nyc 1.6 MB, the rest under 0.5 MB each). `server/osm_data/` is `.gcloudignore`d,
which is why they are staged out to their own directory — the same reason
`.blocks-staging/` exists.

Rebuild them with:

```bash
cd server && ./env/bin/python build_place_labels.py --all --force   # ~6 min, ~100 s of it NYC
```

The local PBFs are a couple of months older than the ones prod's last full
rebuild pulled. That only affects which shops exist, not correctness — labels
are independent of the graph.
